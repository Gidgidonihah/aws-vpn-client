**Build scheme:** Create an "AWSVPNClient" scheme that builds all three targets (VPNCore first, then App and CLI in parallel).

**Approach for project creation:** Use `swift package init` is NOT appropriate here (this is an Xcode project, not SPM). Instead, generate the `.xcodeproj/project.pbxproj` file programmatically or use `xcodegen` if available. If neither is practical, create the project structure manually with the correct pbxproj format. The critical build settings that MUST be correct:
- VPNCore: DEFINES_MODULE = YES, PRODUCT_NAME = VPNCore
- AWSVPNClient: Embeds VPNCore.framework (Embed Without Signing), INFOPLIST_FILE = AWSVPNClient/AWSVPNClient-Info.plist
- aws-connect: RUNPATH_SEARCH_PATHS = @executable_path/../Frameworks, links VPNCore

Check if `xcodegen` is installed (`which xcodegen`). If available, create a `project.yml` spec file and run `xcodegen generate`. If not available, install it via `brew install xcodegen` then generate. XcodeGen is strongly preferred over hand-writing pbxproj (which is error-prone and enormous).

XcodeGen `project.yml` spec:
```yaml
name: AWSVPNClient
options:
  bundleIdPrefix: com.local
  deploymentTarget:
    macOS: "14.0"
  xcodeVersion: "16.3"
  defaultConfig: Debug

settings:
  base:
    SWIFT_VERSION: "6"
    SWIFT_STRICT_CONCURRENCY: complete
    MACOSX_DEPLOYMENT_TARGET: "14.0"

targets:
  VPNCore:
    type: framework
    platform: macOS
    sources:
      - VPNCore
    settings:
      base:
        DEFINES_MODULE: YES
        PRODUCT_NAME: VPNCore

  AWSVPNClient:
    type: application
    platform: macOS
    sources:
      - AWSVPNClient
    info:
      path: AWSVPNClient/AWSVPNClient-Info.plist
      properties:
        LSUIElement: true
        CFBundleName: AWSVPNClient
    dependencies:
      - target: VPNCore
        embed: true
        codeSign: false
    settings:
      base:
        PRODUCT_BUNDLE_IDENTIFIER: com.local.AWSVPNClient
        INFOPLIST_FILE: AWSVPNClient/AWSVPNClient-Info.plist

  aws-connect:
    type: tool
    platform: macOS
    sources:
      - aws-connect
    dependencies:
      - target: VPNCore
        embed: false
    settings:
      base:
        RUNPATH_SEARCH_PATHS: "@executable_path/../Frameworks"
```

After Plan 01 Task 1 builds successfully, perform the mandatory rpath spike:

1. Build all targets: `xcodebuild build -project AWSVPNClient.xcodeproj -scheme AWSVPNClient -configuration Debug`
2. Find the built app bundle in DerivedData: `find ~/Library/Developer/Xcode/DerivedData -name "AWSVPNClient.app" -maxdepth 4 2>/dev/null | head -1`
3. Verify the CLI binary exists inside the app bundle at `Contents/MacOS/aws-connect`
4. Verify VPNCore.framework exists at `Contents/Frameworks/VPNCore.framework`
5. Run `otool -L` on the CLI binary and confirm VPNCore is linked via `@rpath/VPNCore.framework/Versions/A/VPNCore`
6. Run the CLI binary directly from the app bundle: `./AWSVPNClient.app/Contents/MacOS/aws-connect` — it should print "aws-connect v0.1.0 — stub (Phase 4)" without any dyld errors

**If the spike FAILS (dyld: Library not loaded):**
- Check `otool -L` output — if VPNCore path is absolute instead of @rpath, fix RUNPATH_SEARCH_PATHS
- If framework is not in Contents/Frameworks/, add a "Copy Files" build phase to the App target
- If rpath fundamentally cannot work: pivot to local SPM package per CONTEXT.md decision. Create `Package.swift` at project root with VPNCore as a local library target, update both App and CLI targets to depend on it via SPM, and remove the framework target. Document the pivot decision.

**If the spike PASSES:**
- The three-target dynamic framework architecture is confirmed
- No further action needed — Plan 02 can proceed with adding real code to VPNCore
